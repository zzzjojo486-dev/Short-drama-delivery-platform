# 任务卡 T1：商单核心闭环

归属：后端 T1.1–T1.3 / 前端 T1.4–T1.5 / 测试 T1.6。依赖：T1.1→T1.4；T1.2、T1.3→T1.5；T1.4+T1.5→T1.6。
后端卡同样**只给需求+合约，不写实现代码**（讲解+实操）。前端可代写。

## §A 公共约定（本里程碑内硬约束）

- 前缀统一 `/api/`；后台接口带 `/admin/`，前台创作者端接口不带。
- 鉴权：已有 Bearer/JWT。权限类见 `PLAN.md` §2。
- 列表接口统一返回 DRF 分页信封：`{count, next, previous, results}`，可配 `page`、`page_size`（后端限制 `page_size` 上限 100）、筛选参数。
- 统一三层响应（后端最终契约，**取代**旧的 `success` 字段约定）：
  - 成功：HTTP 200，`{"code":200,"message":"操作成功","data":{...}}`；
  - 失败：真实 HTTP 状态码，`{"code":<状态码>,"message":"明确中文提示","data":{}}`；不再返回 `success` 字段；
  - 未登录 401 / 权限不足 403 严格区分。
  - 后台报名列表在 `data` 内额外带 `applications` 别名（同 `results`）；待审核交付列表额外带 `deliveries` 别名（同 `results`）。
- 状态机与字段命名以 `PLAN.md` §3 与 `models.py` 为准。

## §B 状态流转目标（一次完整闭环）

```
运营创建(DRAFT=0) → 提交审核(PENDING=1) → 审核通过→ONLINE=3 ⇄ 驳回→REJECTED=2(可改再提交)
ONLINE 开放报名 → 创作者报名 / 运营指派 → 运营选中参与者→PROGRESS=4
→ 创作者提交交付(待审核) → 审核通过/退回 → 运营确认结单→COMPLETED=5
运营任何阶段可 关闭→CLOSED=6(终态)
```
禁止非法跳转（例如 ONLINE 直接 COMPLETED 应被拒绝）。

## §C 后端接口契约（T1.1/1.2/1.3）

### C1 商单（T1.1）
| 方法/路径 | 权限 | 用途与要点 |
|---|---|---|
| GET `/api/admin/orders/` | 运营 | 列表；筛参 `status, category, search(标题)`；分页 |
| POST `/api/admin/orders/` | 运营 | 创建草稿；字段 `title*, brief, requirement, category, budget`（预算仅展示不结算） |
| GET `/api/admin/orders/{id}/` | 运营/审核员 | 详情（含报名、交付摘要） |
| PATCH `/api/admin/orders/{id}/` | 运营 | 改草稿/驳回单；**上线后的商单不可改内容** |
| POST `/api/admin/orders/{id}/submit/` | 运营 | DRAFT/REJECTED→PENDING 提交审核 |
| POST `/api/admin/orders/{id}/review/` | 审核员 | action=`approve`(→ONLINE)/`reject`(→REJECTED+opinion)，写 reviews |
| POST `/api/admin/orders/{id}/complete/` | 运营 | 结单；**前置（严格）**：状态=PROGRESS，且≥1 名已选中创作者、且每名已选中创作者都有≥1 条 APPROVED 交付、且不存在 PENDING 交付；历史 RETURNED 不阻断；详情接口返回后端计算的 `can_complete` + `complete_blocked_reason` |
| POST `/api/admin/orders/{id}/close/` | 运营 | 任一非终态→CLOSED |

### C2 报名+指派（T1.2）
| 方法/路径 | 权限 | 用途与要点 |
|---|---|---|
| POST `/api/orders/{id}/apply/` | 用户(创作者 role3) | 报名，字段 `proposal`（≤2000）；仅 ONLINE 可报；每人限报一次（重复→400） |
| GET `/api/admin/orders/{id}/applications/` | 运营 | 报名列表（谁报、说明、状态）；分页，`data` 带 `applications` 别名 |
| POST `/api/admin/orders/{id}/applications/{aid}/select/` | 运营 | 选中参与者；**首次选中即** ONLINE→PROGRESS；`selected=true`；重复选中→400 |
| POST `/api/admin/orders/{id}/assign/` | 运营(0/1) | 指派创作者，body `{"creator_id":123}`；仅 ONLINE/PROGRESS；目标仅 role3；复用已有报名（无则新建 selected=true 的报名）；重复→400；事务+唯一约束兜底 |

### C3 交付（T1.3）
| 方法/路径 | 权限 | 用途与要点 |
|---|---|---|
| POST `/api/orders/{id}/deliver/` | 用户 | 提交交付；`delivery_type` 二选一：`video`(上传文件≤1GB) / `link`(填外链)；字段 `delivery_type*, video_file / video_url, note`；交付后该商单进入待审核交付 |
| GET `/api/admin/reviews/deliveries/` | 审核员 | 待审核交付列表（状态=PENDING 且商单=PROGRESS）；分页，`data` 带 `deliveries` 别名 |
| POST `/api/admin/deliveries/{id}/review/` | 审核员 | 审核交付（接 T0.1 修复） |
| GET `/api/orders/{id}/` | 用户 | 创作者端详情：商单信息 + 我是否已报名 + 我的交付记录 |
| GET `/api/orders/` | 用户 | 可报名/进行中的商单列表（报名入口） |

**交付提交规则**：仅报名且被选中(或已被指派)的创作者可提交（否则 403）；PROGRESS 状态商单可提交；已 APPROVED 的交付不能再重复提交同单；存在 PENDING 交付时也不能重复提交；退回(RETURNED)后可再交。`delivery_type` 二选一：`video`(上传 MP4 文件，≤1GB，流式写盘) / `link`(填 http/https 外链，≤500 字符)，二者严格互斥。

> **待后端确认的决策点**：需求文档 §5.5 有「报名截止」。当前 Order 模型无 `deadline` 字段。建议补字段+迁移（推荐，简单），或本版用 category/description 承载。由后端会话讲解时和用户定，改文档再动代码。

## §D 前端契约（T1.4/T1.5）

- `/admin/orders`：列表（状态/分类筛+分页）→ 详情 → 「创建」表单页；详情页含：需求信息、报名列表+选中、交付记录、审核入口、结单/关闭按钮（按角色显隐）
- `/admin/orders/create`：创建表单（title/brief/requirement/category/budget），保存后进草稿列表
- 创作者端（前台，登录用户可见）：商单列表页显示「可报名 / 已报名 / 进行中 / 已结单」状态；已入选显示「提交交付」入口（video/link 二选一）
- 路由统一挂 `/admin/*` 与前台路由，守卫沿用 `requiresAdmin`

## §E 测试要点（T1.6）

按角色造数据走串：运营创建→提交→审核员通过→用户报名→(可选指派)→运营选中→用户交付(视频与链接各一)→审核员通过/退回→再次交付→通过→运营结单。断言每一步状态机符合 §B、非法跳转被拒、权限 403 正确。

## §F 验收标准（本里程碑完成定义）

1. 状态机严格按 §B，非法跳转被拒
2. 报名与指派都生效；交付两种方式都能进待审；退回可重新交付
3. 结单前置条件成立才可结单
4. 前端页面与后端接口字段一一对应，无契约偏差
5. 测试点 §E 全过
