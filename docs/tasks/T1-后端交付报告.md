## 2. 最终接口与 JSON 示例

统一响应（三层）：

- 成功：HTTP 200 `{"code":200,"message":"操作成功","data":{...}}`
- 失败：真实 HTTP 码 `{"code":<码>,"message":"明确提示","data":{}}`，无 `success` 字段
- 401=未登录；403=已登录但角色/权限不足

### 2.1 商单管理（后台，`/api/admin/orders/...`，角色 0/1，审核接口角色 2）

| 方法/路径 | 权限 | 说明 |
|---|---|---|
| GET `/api/admin/orders/` | 0/1 | 列表；`status/category/search` 筛选；分页 |
| POST `/api/admin/orders/` | 0/1 | 建草稿；`title* brief requirement category budget` |
| GET `/api/admin/orders/{id}/` | 0/1/2 | 详情（含报名、交付、结单判断） |
| PATCH `/api/admin/orders/{id}/` | 0/1 | 仅 DRAFT/REJECTED 可改 |
| POST `/api/admin/orders/{id}/submit/` | 0/1 | DRAFT/REJECTED → PENDING |
| POST `/api/admin/orders/{id}/review/` | 2 | `action=approve/reject`（reject 必填 opinion）；PENDING → ONLINE/REJECTED |
| POST `/api/admin/orders/{id}/complete/` | 0/1 | PROGRESS + 严格前置 → COMPLETED |
| POST `/api/admin/orders/{id}/close/` | 0/1 | 非终态 → CLOSED |
| GET `/api/admin/orders/{id}/applications/` | 0/1 | 报名列表（分页，`data.applications` 别名） |
| POST `/api/admin/orders/{id}/applications/{aid}/select/` | 0/1 | 选中；ONLINE/PROGRESS → PROGRESS |
| POST `/api/admin/orders/{id}/assign/` | 0/1 | 指派 `{"creator_id":123}` |
| GET `/api/admin/reviews/deliveries/` | 2 | 待审交付（PENDING 且商单 PROGRESS；`data.deliveries` 别名） |
| POST `/api/admin/deliveries/{id}/review/` | 2 | 交付审核 approve/reject |

**列表返回示例**（`GET /api/admin/orders/`）：

```json
{
  "code": 200, "message": "操作成功",
  "data": {
    "count": 1, "next": null, "previous": null,
    "results": [{"id": 1, "title": "短剧征稿", "status": 4, "publisher": 2, "...": "..."}]
  }
}
```

**详情返回示例**（`GET /api/admin/orders/{id}/`）：

```json
{
  "code": 200, "message": "操作成功",
  "data": {
    "order": {
      "id": 1, "title": "短剧征稿", "status": 4,
      "applications": [{"id": 1, "creator": 5, "selected": true, "proposal": "我来", "creator_name": "张三"}],
      "deliveries": [{"id": 2, "creator_id": 5, "delivery_type": "video", "video_file": "http://host/media/deliveries/xxx.mp4", "status": 1}],
      "can_complete": true, "complete_blocked_reason": null
    }
  }
}
```

**指派返回示例**（`POST /api/admin/orders/{id}/assign/` body `{"creator_id":123}`）：

```json
{"code": 200, "message": "操作成功", "data": {
  "application": {"id": 3, "creator": 123, "selected": true, "proposal": ""},
  "order": {"id": 1, "status": 4}
}}
```

### 2.2 创作者端（前台，`/api/orders/...`，登录用户）

| 方法/路径 | 权限 | 说明 |
|---|---|---|
| GET `/api/orders/` | 登录 | 可见商单（ONLINE/PROGRESS 或我有报名） |
| GET `/api/orders/{id}/` | 登录 | 详情：商单 + 我的报名 + 我的交付（含审核记录） |
| POST `/api/orders/{id}/apply/` | 角色 3 | 报名 `proposal`(≤2000)；仅 ONLINE；去重 |
| POST `/api/orders/{id}/deliver/` | 角色 3 | 交付；PROGRESS + 已入选；video/link 二选一 |

**创作者列表项**（`GET /api/orders/`，`data.results[]`）：

```json
{"id": 1, "title": "短剧征稿", "status": 3,
 "is_applied": true, "is_selected": false, "can_apply": false, "can_deliver": false}
```

**创作者详情**（`GET /api/orders/{id}/`）：

```json
{"code": 200, "message": "操作成功", "data": {
  "order": {"id": 1, "title": "短剧征稿", "status": 4},
  "is_applied": true, "is_selected": true, "can_apply": false, "can_deliver": true,
  "application": {"id": 1, "proposal": "我来", "selected": true},
  "deliveries": [{"id": 2, "delivery_type": "video", "video_file": "http://host/media/deliveries/xxx.mp4", "status": 1, "reviews": []}]
}}
```

**交付请求**：`delivery_type=video` 用 multipart 上传 `video_file`（MP4，≤1GB）；`delivery_type=link` 传 JSON `video_url`（http/https，≤500 字符）。二者互斥。

### 2.3 媒体服务

`GET /media/deliveries/{file}` 支持 `Range`：完整返回 200 + `Accept-Ranges: bytes`；`bytes=0-99` 返回 206 + `Content-Range`；不存在返回 404。

## 5. 已验证流程

1. 运营创建草稿 → 提交审核 → 审核员通过上线。
2. 创作者报名（仅 ONLINE、去重、限角色 3）→ 运营选中（或 `assign` 指派）→ 进入 PROGRESS。
3. 创作者提交交付（视频小文件真实上传 / 外链）→ 待审 → 审核员通过/退回 → 退回后可再交。
4. 多创作者：每人均有 APPROVED 且无 PENDING 时才可结单；`can_complete=false` 时详情返回 `complete_blocked_reason`。
5. 媒体服务冒烟：完整 200（`Content-Type: video/mp4`、`Accept-Ranges: bytes`）、Range 206（`Content-Range: bytes 0-99/1036`）、缺失 404。
6. 事务回滚：审核失败/选中失败/指派 IntegrityError 时数据库状态回滚。
7. 唯一约束迁移成功应用 MySQL，唯一索引存在。

## 6. 未验证项 / 风险

- **真实 1GiB 上传**未做端到端实测（仅用 `MAX_DELIVERY_VIDEO_BYTES` 打桩为 10 字节做了流式超限分支的单元验证）。1GB 是流式写盘 + 边写边累计字节数的逻辑判断，未跑真实 1GB 文件。
- **反向代理/部署层请求体上限**未验证（如 Nginx `client_max_body_size`、网关超时），超出 1GB 会在到达应用前被代理拦截或超时，需部署侧配合。
- **媒体内容真伪校验**仅检查扩展名 `.mp4`，未做内容嗅探/转码/病毒扫描；不声称完整媒体安全。
- **MySQL 并发**未单独压测（仅靠 `select_for_update` + 唯一约束 + 事务保证，未做双请求并发验证）。

## 7. 前端需配合调整

- 所有接口响应改为三层 `{code,message,data}`，去掉对旧 `success` 字段的读取。
- 列表仍读 `data.count/next/previous/results`；后台报名列表另读 `data.applications`、待审交付列表另读 `data.deliveries`。
- 结单按钮依据详情 `data.order.can_complete` 显隐/置灰，失败时展示 `complete_blocked_reason`。
- 指派：调用 `POST /api/admin/orders/{id}/assign/`，body `{"creator_id": ...}`（不再依赖 `user_id` 前端自选，创作者身份由后端 JWT 决定）。
- 交付视频走 multipart 字段 `video_file`，外链走 JSON 字段 `video_url`；二者互斥，前端需做二选一交互。
- 创作者端详情/列表新增 `is_applied/is_selected/can_apply/can_deliver` 驱动按钮显隐。
