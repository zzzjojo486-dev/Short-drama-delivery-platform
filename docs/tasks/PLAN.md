## §2 角色与权限常量（共享，勿各自发明）

| 数值 | 角色 | 权限要点 |
|---|---|---|
| 0 | SUPER_ADMIN 超管 | 全部功能；改角色/分配角色**仅超管** |
| 1 | OPERATOR 运营 | 商单管理、仪表盘、用户查询 |
| 2 | REVIEWER 审核员 | 三类审核 |
| 3 | USER 普通用户 | 前台社区 + 报名/交付 |

## §3 状态机常量

**商单 Order.status**（7 态，来自 models）：DRAFT=0 草稿 → PENDING=1 待审核 → ONLINE=3 已上线(开放报名) → PROGRESS=4 进行中(已选参与者) → COMPLETED=5 已完成(结单)；分支：REJECTED=2 已驳回(可改再提交)、CLOSED=6 已关闭(终止，终态)。

**交付 OrderDelivery.status**（3 态）：PENDING=0 待审核 → APPROVED=1 已通过 → RETURNED=2 退回修改(可重新交付)。

**审核 Review.action**：APPROVE=1 通过，REJECT=2 驳回。`target_type`：`order` / `delivery` / `post` / `comment`。

**交付类型**：VIDEO=0 视频，LINK=1 外链。

## §4 任务台账（进度在 PROGRESS.md）

### P0 阻断修复（后端）
- **T0.1** 交付审核接口修复（当前引用不存在的 `STATUS_APPROVED/STATUS_REJECTED`，且字段类型写错）。卡片：`T0-阻断修复.md`。
- **T0.2** 改角色接口权限由 IsAdminStaff 收紧为 `IsSuperAdminStaff`（文档规定仅超管可分配角色）。

### P1 商单核心闭环
- **T1.1** 商单：创建/提交审核/列表(状态/分类筛选+分页)/详情/上线审核/结单/关闭。运营商单看板契约。卡片：`T1-商单核心闭环.md`。
- **T1.2** 报名+指派：创作者报名、运营查看报名并选中参与者。
- **T1.3** 交付提交：视频上传(≤1GB)或外链二选一；前置/交付记录。
- **T1.4** 前端：`/admin/orders` 列表+创建+详情（报名列表/交付记录/审核入口）。
- **T1.5** 前端：创作者端「可报名 / 提交交付」入口。
- **T1.6** 测试：报名→指派→交付→审核→结单全流程接口测试。

### P2 三类审核+仪表盘
- **T2.1** 审核聚合待办（order/delivery/post/comment 统一入口）+ 审核历史查询。
- **T2.2** 仪表盘统计接口（用户/商单/待审商单/待审交付/待审社区内容，真实计数）。
- **T2.3** 前端 `/admin/reviews` 聚合页 + `/admin/dashboard`。
- **T2.4** 测试：三类审核流程 + 仪表盘计数与库里核对。

### P3 用户+社区管理
- **T3.1** 用户管理：分页/搜索/详情/禁用启用；设角色超管专属（接 T0.2）。
- **T3.2** 社区内容：帖子/评论列表+下架留痕。
- **T3.3** 前端 `/admin/users` 完善 + `/admin/contents`。
- **T3.4** 测试：禁用账号不可登录/报名；下架内容不可见。

### P4 收尾
- **T4.1** audit_logs 操作留痕（审核/禁用/下架等关键操作）。
- **T4.2** 前端主题色（深色系+品牌色）微调 + 旧文案终检。
- **T4.3** 总体：全流程联调 + v1.0 验收要点（文档 §12）走查。
