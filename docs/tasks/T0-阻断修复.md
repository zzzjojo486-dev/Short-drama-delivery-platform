## T0.1 交付审核接口修复

**现状（已由总体上盘确认）**：`django_backend/apps/orders/views.py` 中的 `DeliverReviewView` 有两个 bug：

1. 引用 `OrderDelivery.STATUS_APPROVED` / `STATUS_REJECTED`，但模型里实际是 `APPROVED=1` / `RETURNED=2`（见 `models.py`）→ 会抛 `AttributeError`。
2. 把请求传来的字符串 `'approve'/'reject'` 直接写进 `Review.action`（整数字段，取值应为 `Review.APPROVE=1` / `Review.REJECT=2`）→ 存入类型错误。

**需求**：修复后接口语义为——

`POST /api/admin/deliveries/{id}/review/`（审核员 REVIEWER=[0,2]）：
- 请求体：`action`（取值 `approve|reject`）+ `opinion`（驳回必填审核意见，通过可空）
- `approve`：交付 `status` → `APPROVED=1`；`reject`：交付 `status` → `RETURNED=2`（退回可重新交付）
- 每条审核写一条 `reviews` 记录：`target_type='delivery'`、`target_id=交付ID`、`reviewer=当前用户`、`action=数值1或2`、`opinion=意见`
- 非法 `action` 返回 4xx 明确错误，不得 500

**验收标准**：
1. 审核员账号对待审核交付 post `approve` → 交付状态变为 1，`reviews` 新增一条 `action=1`
2. post `reject` + opinion → 交付状态变为 2，`reviews` 新增一条 `action=2`
3. post 非法 action → 返回 4xx，不产生记录
4. 交付不存在 → 404
5. 普通用户/无法访问 → 403
6. 前端 `AdminReviews.vue` 的「通过/驳回」能走通

## T0.2 改角色权限收紧为仅超管

**现状**：`PATCH /api/admin/users/{id}/role/` 用的权限是 `IsAdminStaff`（超管0/运营1/审核员2 都能改）。

**需求**：按需求文档 §5.4「为用户分配角色（超管可操作）」，改为**仅超管**（`IsSuperAdminStaff`，即 role=0）可调用。

**验收标准**：
1. 超管可改任意用户角色
2. 运营/审核员调用返回 403
3. 普通用户无法进入后台（已有，回归确认）
