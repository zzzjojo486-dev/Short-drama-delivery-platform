# docs/tasks/ 协作约定

本目录是「短剧交付平台」分区改造的**共同契约**，四个会话都以此为据。改动仓库代码前，请先读本文件。

## 四个会话分工

| 会话 | 职责 | 在代码里的活动范围 |
|---|---|---|
| **总体（本会话）** | 排计划、派任务、对进度、做联调验收 | 仅写本目录文档 + main 上合并验证，不写业务代码 |
| **后端** | 商单/权限/审核等后端实现，按「讲解+实操」带用户亲手写 | `django_backend/` |
| **前端** | Vue 页面与 API 封装实现（可代写） | `frontend/` |
| **测试** | 按契约验证接口与流程、冒烟、回归 | 一般为只读验证或写测试代码 |

## 认领与汇报流程

1. 读 `PLAN.md` → 找归属自己的任务（可并行，看依赖）
2. 读对应任务卡 `T*-*.md` → **契约部分就是硬约束**，接口字段以卡内为准
3. 在本分区分支上实现（见下「分支规则」）
4. 开工把 `PROGRESS.md` 里自己的任务状态改「进行中」；完成后改「完成」，并写一句验证说明
5. 完成关键里程碑后知会总体，由总体在 main 合并并做联调

**改契约=改文档**：任何人觉得接口字段、状态机、权限需要调整，先到本目录改文档再动代码，避免前后端各自理解。

## 分区纪律

- **后端「讲解+实操」**：任务卡只写「需求 + 验收标准」，**不写实现代码**。后端会话负责讲解原理，由用户亲手敲代码。
- **前端可协助实现**：前端会话可以代写页面与封装。
- **状态机与角色是共享常量**：见 `PLAN.md` §2/§3，所有分区按同一套数值编号，禁止各自发明。

## 分支规则（用户已确认：各分区独立分支）

- `main`：主线；总体在此合并验证
- 后端分区 → `feat/backend`
- 前端分区 → `feat/frontend`
- 测试分区：写测试代码用 `feat/test`，一般只读验证直接在 main
- 任务文档的更新直接提交到 main（本目录由总体和所有分区共同维护）

## 更新本目录

所有会话都能改本目录；`PROGRESS.md` **每个会话只更新自己那几行的状态与备注**，避免冲突。提交粒度要小，方便总体核对进度。
