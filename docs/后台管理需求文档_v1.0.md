## 1. 项目背景与目标

现有项目是一个「小红书式」内容社区（用户注册登录、发帖、评论、点赞、收藏、私信、关注），
基于 **Django REST Framework (DRF) + MySQL** 后端、**Vue 3 + Vite + Element Plus** 前端。

本次改造目标：

1. **前端品牌改版**：将界面文案从「小红书」风格改为「短剧交付平台」风格。
2. **新增后台管理系统**：面向平台运营人员，提供**商单发布与管理、内容审核、用户与社区管理、角色权限**等功能。
3. 技术路线：后端由开发者**亲手实操学习并实现**（Claude 负责讲解与指导），前端可由 Claude 协助实现。

后台管理的核心业务是 **「商单」**：客户/平台发布一个短剧商单需求 → 创作者报名 →
创作者交付成品短剧 → 审核员审核 → 通过则结单。平台通过商单连接「品牌方需求」和「创作者产能」。

> 本版为 v1.0，**不含资金结算**。涉及报价、佣金、结算的模块留到 v1.1 及以后迭代。

## 2. 角色与权限模型（多角色分级）

后台采用**多角色分级**,引入 `role` 概念。v1.0 定义三类后台角色 + 普通用户：

| 角色 | 标识 | 职责 | 可访问的后台功能 |
|---|---|---|---|
| 普通用户 | USER | 平台创作者，可报名商单、交付成品、浏览社区 | 前端社区 + 商单报名/交付 |
| 运营 | OPERATOR | 发布/管理商单，推进商单流程 | 商单管理、仪表盘、用户查询 |
| 审核员 | REVIEWER | 审核各类内容 | 商单需求审核、成品短剧审核、社区内容审核 |
| 超级管理员 | SUPER_ADMIN | 全局管理，管角色/用户/权限 | 全部功能，含用户与角色管理 |

权限规则要点：

- **后台与前台权限分离**：同一个登录体系（复用现有 User），通过 `role`/权限字段区分能否进入后台，以及能操作哪些后台模块。
- **细粒度权限**：每个后台模块按「查看 / 新增 / 修改 / 删除 / 审核」做权限控制。v1.0 以「角色 + 模块」授权即可，权限表为后续扩展预留。
- **普通用户默认无后台权限**，仅当被后台授权为运营/审核员/超管后才可登录后台。

## 3. 商单全流程（报名 – 交付 – 审核）

商单生命周期的核心状态流转（v1.0）：

```
商单需求创建
   ↓  提交/上线
商单需求待审核 ──审核不通过──▶ 已驳回（附原因）
   ↓ 审核通过
商单已上线（向创作者开放报名）
   ↓ 创作者报名 / 运营指派
报名、指派收集中
   ↓ 运营确定参与者
商单进行中（已选中的创作者提交/交付成品）
   ↓ 创作者提交成品
交付待审核 ──审核不通过──▶ 退回修改（附意见，可重新交付）
   ↓ 审核通过
交付已通过
   ↓ 运营确认结单
商单已完成（结单）
```

关键说明：

- **报名制**：商单上线后，普通用户（创作者）可报名，附报名说明。
- **指派制**：运营也可直接指定某创作者参与商单（报名 + 指派二者都支持）。
- **交付物（两种方式）**：
  - **视频短剧提交**：创作者上传成品短剧视频文件到平台，上限 **1GB**，后台可预览并审核。
  - **链接短剧提交**：创作者填写外部视频链接，后台/前台展示时跳转到外部链接。
- **退回修改**：审核不通过的成品，退回给创作者重新交付，可重复，直至通过或运营终止。
- **结单**：审核全部通过后，由运营确认结单，商单关闭。

（v1.0 暂不涉及酬金、结算。商单上**展示**「预算/报价」字段，仅展示、不结算。）

> 后续（不在 v1.0）：后台可挑选优秀短剧作为**外部作品展示**。本版不做。

## 4. 审核管理

后台需审核三类内容（均记录**审核人、审核动作、审核意见、审核时间**）：

| 审核对象 | 说明 | 通过后动作 | 驳回后动作 |
|---|---|---|---|
| 商单需求内容 | 平台运营代录入创建的商单需求，上线前需审核（无外部客户账号） | 商单进入「已上线/开放报名」 | 商单驳回，附修改意见 |
| 商单成品短剧 | 创作者交付的成品视频 | 交付「已通过」→ 可结单 | 退回，附意见，创作者重新交付 |
| 用户社区内容 | 用户日常发布的帖子/评论 | 正常展示 | 内容下架/隐藏，附原因 |

> 注意：本次需求中「创作者入驻」审核**未列入 v1.0**（用户回答未勾选）。若后续需要「创作者入驻需审核」，
> 放入 v1.1 迭代，届时在 User 上增加入驻审核状态即可。

## 5. 功能模块清单

### 5.1 后台登录与鉴权（AUTH-ADMIN）
- [ ] 复用现有账号登录；根据 `role` 判断是否允许进入后台
- [ ] 无权限用户禁止访问后台接口（返回 403）
- [ ] 登录后基于 JWT 携带角色/权限信息
- [ ] 退出登录

### 5.2 仪表盘（DASHBOARD）
- [ ] 核心统计：用户总数、商单总数、待审核商单数、待审核交付数、待审核社区内容数（统计均为**数据库真实计数**）
- [ ] 按时间展示商单/交付趋势（简单列表/图表即可）

### 5.3 用户管理（USER-ADMIN）
- [ ] 用户列表：分页、按用户名/昵称搜索
- [ ] 查看用户详情（基本资料 + 其参与/交付的商单）
- [ ] 启用 / 禁用账号（禁用后不可登录、不可报名/交付）
- [ ] 角色信息展示（是否为运营/审核员/超管）

### 5.4 角色与权限管理（ROLE）
- [ ] 查看角色列表
- [ ] 为用户分配角色（超管可操作）
- [ ] （预留，v1.0 可不做）模块级权限的增删改

### 5.5 商单管理（ORDER）
- 发布：
  - [ ] 创建商单需求：标题、需求描述（Brief）、交付要求/规格、分类、报名截止等
  - [ ] 预算/报价字段在界面上**展示**（仅展示，不参与结算）
  - [ ] 提交审核 → 走审核流程
  - [ ] 审核通过后自动/手动上线开放报名
- 报名&指派：
  - [ ] 查看报名列表（谁报了名、报名说明）
  - [ ] 选择/指派参与者
- 流程推进：
  - [ ] 查看某商单下的交付记录
  - [ ] 确认结单
  - [ ] (超管/运营) 终止/关闭一个商单
- 列表与搜索：
  - [ ] 商单列表：按状态、标题、分类筛选，分页

### 5.6 交付管理（DELIVERY）
- [ ] 创作者在前台提交交付物 → 进入「待审核」；交付方式**二选一**：
  - [ ] **视频短剧提交**：上传成品视频文件（≤1GB），平台存储后待审核
  - [ ] **链接短剧提交**：填外部链接，跳转展示
- [ ] 提交交付物后其相关商单进入交付评审阶段
- [ ] 记录每次交付的时间、类型、审核结果、审核意见（可多次交付）

### 5.7 审核管理（REVIEW）
- [ ] 待办列表聚合：所有待审核对象统一入口（商单需求 / 成品短剧 / 社区内容）
- [ ] 单个审核：查看内容详情（商单需求、成品视频预览、帖子/评论），通过或驳回，填意见
- [ ] 审核历史：可查某对象的历史审核记录

### 5.8 社区内容管理（CONTENT-ADMIN）
- [ ] 帖子/评论列表（分页、筛选、搜索）
- [ ] 下架违规帖子/评论，附原因
- [ ] （可选）查看被下架内容及处理记录

### 5.9 后台通用能力（COMMON）
- [ ] 分页、搜索、筛选统一交互
- [ ] 操作留痕日志（谁在什么时间做了什么操作）※ v1.0 至少记录审核与禁用等关键操作
- [ ] 反馈/错误提示

## 6. 非功能需求

### 6.1 安全
- [ ] 后台接口统一做角色/权限校验（DRF Permission + 自定义权限类）

## 7. 数据模型建议（在现有 schema 基础上新增）

> 现有表不变。新增以下表支撑后台功能。

| 表 | 关键字段 | 说明 |
|---|---|---|
| `orders`（商单） | id, title, brief, category, spec/要求, status, publisher_id, created_at | 商单主表，status 为状态机 |
| `order_applications`（报名） | id, order_id, creator_id, proposal, status, created_at | 创作者报名 |
| `order_deliveries`（交付） | id, order_id, creator_id, type(视频/链接), video_file, video_url, note, status, created_at | 成品交付，可多次 |
| `reviews`（审核记录） | id, target_type, target_id, reviewer_id, action(通过/驳回), opinion, created_at | 统一审核留痕 |
| `audit_logs`（操作日志） | id, operator_id, action, target_type, target_id, detail, created_at | 后台关键操作留痕（可后置实现） |

User 表建议新增字段（通过迁移 `manage.py makemigrations`）：

| 字段 | 说明 |
|---|---|
| `role`（或 `is_staff` + `role`） | 区分 USER / OPERATOR / REVIEWER / SUPER_ADMIN |
| `is_active_enabled`（禁用状态） | 账号启用/禁用 |

> 角色粒度若未来要「一人多角色 / 模块级细权限」，可演进为 `roles` 表 + `user_roles` 多对多，v1.0 先用单字段 `role` 简化实现。

## 8. 接口概要（API 初步规划）

统一前缀 `/api/`，后台接口建议复用当前 DRF 结构，新增 App（如 `apps/admin_panel`）。

| 方法 | 路径 | 说明 | 权限 |
|---|---|---|---|
| POST | `/api/admin/login` | 后台登录（校验角色） | – |
| GET | `/api/admin/dashboard/` | 仪表盘统计 | OPERATOR+ |
| GET | `/api/admin/users/` | 用户列表 | OPERATOR+ |
| PATCH | `/api/admin/users/{id}/` | 禁用/启用/设角色 | SUPER_ADMIN |
| GET/POST | `/api/admin/orders/` | 商单列表/创建 | OPERATOR |
| PATCH | `/api/admin/orders/{id}/` | 商单流转/结单 | OPERATOR |
| GET | `/api/orders/` | 创作者端商单列表（报名入口） | USER |
| POST | `/api/orders/{id}/apply/` | 创作者报名 | USER |
| POST | `/api/orders/{id}/deliver/` | 创作者提交交付（视频上传 ≤1GB，或外链 `video_url`） | USER |
| GET | `/api/admin/reviews/pending/` | 待办审核列表 | REVIEWER |
| POST | `/api/admin/reviews/{id}/review/` | 通过/驳回 | REVIEWER |
| GET | `/api/admin/contents/` | 社区内容管理列表 | REVIEWER/OPERATOR |
| PATCH | `/api/admin/contents/{id}/` | 下架/隐藏 | REVIEWER |

> 报名、交付等属于创作者在前台的操作，虽归属商单业务，但鉴权用普通用户角色。具体接口按实现时细化。

## 11. 需求确认结论

此前列为「待确认项」的问题均已定稿：

1. **成品短剧提交方式**：分为「**视频短剧提交**」（上传视频文件至平台，≤1GB）与「**链接短剧提交**」（填外部链接跳转展示）两种，创作者二选一。
2. **商单需求创建**：由**平台运营代录入**，不设外部客户账号。
3. **是否区分客户/品牌账号**：**否**，v1.0 由运营统一录入。
4. **违规内容申诉通道**：v1.0 **不做**。
5. **仪表盘数据**：采用**真实计数**（数据库实际数据统计）。
6. **商单预算/报价字段**：界面上**展示**（仅展示，不参与结算）。
7. **优秀短剧外部展示**：后续版本再做，**v1.0 不做**。

## 12. 验收要点（示例）

- 用不同角色登录后台，只能看到并操作授权范围内的模块；无权限返回 403。
- 商单从「创建→审核→上线→报名→指派→交付→审核→结单」全流程可走通，状态不越级跳转。
- 审核通过的成品进入可结单；审核驳回的成品可被创作者重新交付。
- 对违规社区内容可下架，并记录处理人与原因。
- 无权限账号（普通用户）无法进入任何后台页面/接口。
- 前端品牌文案整体已由「小红书」改为「短剧交付平台」（无遗留旧文案）。
